# Lesson 5 — Principles

*Session 3. Read time: ~10 minutes. Hard-won rules — every one of these was paid for with a real mistake. Re-read this lesson after your first project; half of it only clicks once you've been bitten.*

## 1. Short sessions, fresh starts
One task, one session. Done = commit = new session. Long meandering sessions end in the dumb zone, and the dumb zone ends in mess.

## 2. Log everything
Keep a running `log.md` in every project: date, what was done, what's next. Your future self — and every future Claude session — starts from the log instead of from zero. The habit that compounds most.

## 3. Mistakes are architecture problems, not AI problems
When Claude Code keeps getting something wrong, the cause is usually upstream: a messy folder, a missing CLAUDE.md rule, an ambiguous plan. Don't scold the model — fix the setup. Clear structure in, good work out.

## 4. Do not trust — verify
Confident and correct are different things (see: hallucination). Check claims, open outputs, run the thing. Trust grows per-task-type as verification keeps passing; it is never granted globally.

## 5. Ask until you understand
When Claude does something you don't follow, ask it to explain — it's a patient teacher with infinite time. Never accept magic. Each explanation converts "it did something" into a skill you own.

## 6. Caps on everything, day one
Spending limits on every account and every API *before* first use. Not because disasters are likely — because uncapped accounts turn a small mistake into an expensive one. A cap turns "catastrophe" into "hm, hit my limit." When you add a paid API later: look up the official price per request, multiply by how many requests you'll make, and check that number *before* running anything in bulk.

## 7. Plan first; let Claude write the brief
The messy-idea → "write me a clear prompt for this" → correct-the-plan move ([Lesson 4](04-workflow.md)) is the single biggest quality lever a beginner has.

## 8. Context is the real skill
You're not writing clever prompts; you're deciding what the model gets to see — the right files, the right instructions, the right history, nothing else. A mediocre prompt with the right context beats a brilliant prompt with the wrong one.

## 9. Teach the system, not just yourself
Corrected Claude twice on the same thing? Put the rule in CLAUDE.md. Explained a workflow twice? Make it a skill. Every lesson captured makes every future session smarter — improvement compounds like interest.

## 10. Close the loop
The endgame beyond this course: define "done" so clearly that Claude can check its own work (tests, checklists, evals) and retry until it passes. The experts' progression: you stop writing prompts and start designing loops. Plant the flag now; grow into it.

## 11. Finish things
No half-features, no "TODO later" for the core thing. A small finished project teaches more than three abandoned ambitious ones.

---

**The three you'll break first** (everyone does): #1 (the session that ran too long), #4 (the output you shipped unchecked), #11 (the second project started before the first was finished). Breaking them once, noticing, and understanding why the rule exists — that's the lesson working.
